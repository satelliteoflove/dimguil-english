1. Settings screen layout

Changed

The setting names were placed by a table of x positions that right-aligned the Japanese at x = 160 (160 minus 12 px per character). In English that left the names ragged on both sides, and "Spell Names" ran into its "(". Every name now starts at x = 80. The widest, "Monster Names", ends 8 px before its "(", and the names with their options sit centred on the screen. The title and "Done" keep their places.

The same table is in the Edge of Town overlay and again in the maze overlay; both are changed. I saw the Edge of Town copy on screen. The maze copy has the same bytes but I haven't opened the in-maze settings on the new build.

3. Inn room help lines

Changed

Every room's help line lost its end ("Restores all HP for 10000G a"). Each town screen divides 720 glyph sprites among four text layers, but most screens only handed out 640. The room list's padding spaces are sprites too, and they filled the main layer. The Inn keeps the town map's layers, so the town map now gives the main layer 172 instead of 154: the list is 133 sprites and the help bar shows about 39 glyphs. No other screen changes. All allocation in town goes through one routine, and the crawl found nothing else using the spare sprites.

4. Change Name keyboard

Changed

Create Character already opened its keyboard on English letters. Change Name has its own way in, which still reset the keyboard to hiragana. It now opens on English letters too; SELECT still cycles through hiragana and katakana.

5. Letter pairs in 55 town strings

Changed

The regular font has single glyphs for common letter pairs, and the encoder uses them for any string marked to be packed. 55 strings in SISETU that are drawn in that font weren't marked. They are Boltac's help lines, the recruits' and the fortune teller's speeches, the King's, the Inn's level-up lines and the temple's chant. They drew one sprite per letter, which is how lines run out of sprites. Wording is unchanged and the text looks the same; it just takes fewer sprites. The longest town string went from 445 bytes to 305. The bold menu labels stay unpacked, because that font has other glyphs in the pair cells ("Sort Items" packed drew as "S∂/I3ms").

6. Monster Compendium check

No problems found

The Compendium and the catalog don't draw through the sprite pool the town crawl read, so it couldn't see them. They use a renderer that points one sprite at each glyph in turn, every frame. The crawler now watches that sprite and logs each glyph it draws, so these screens come out as text like the others.

I crawled all 14 categories, 249 screens. Every one of the 216 monster descriptions was reached (0 missed), along with 218 monster names. Checks:

  • Every description line matches the script, with no cut lines and no untranslated glyphs. Flags other than built-in names: none.
  • The longest line ends at x = 320; the text panel's inner edge is at 324. The lowest line starts at y = 186 and the panel ends at 226.
  • Monster names (the bold font) come from the game's built-in English list, not our files, so the report can't match them to a string. That's expected.

7. Boltac's catalog check

Descriptions fine Two findings below

Same method, one crawl per top category, 1011 screens. All 306 item descriptions were reached (0 missed), 1669 distinct lines. All match the script, with no cut lines and no untranslated glyphs. The one line the report couldn't match, "A strange Eastern flail made", is the start of the catalog entry that holds two items' descriptions (an old quirk of the file), and it draws correctly. The longest line ends at x = 318; the parchment's edge is at 325. The lowest line starts at y = 211, with the parchment ending at 227.

8. "Jpn" item names were garbled

Changed after review

The settings screen offers Japanese or English names for items, monsters and spells, and for the status words. The patch translates the English name file (I_NAME_E) and leaves the Japanese one (I_NAME_J) as it was. The English font has no kana, so with Item Names on "Jpn" the catalog draws the Japanese list as a jumble of kanji and Latin letters. A new game starts on "Eng" (the cold-boot test states do), so only a player who flips the switch sees this. I tested Item Names only. Monster Names, Spell Names and Status probably behave the same, but I haven't checked them.

You decided the patch is English-only. The four switches are now locked on "Eng": the settings screens in town, at camp and in a card battle no longer move them, and loading a save sets them to English. "Jpn" stays on screen, dimmed. The readme and the announcement should say the patch is English-only. The screenshots above are from before the change.

9. Finding: long item names are crammed in the catalog list

Not changed: your call

The catalog's item list wraps a name longer than about 10 letters onto a second line only 6 px lower, so both lines squeeze into one row and touch the next name. It's hard to tell where one name ends and the next begins ("SWORD OF / SWISHES / BLADE OF / BITING"). These are the developer's uppercase English names, shown with Item Names on "Eng", so the original game probably does the same. I couldn't confirm that, because the Japanese disc ignores input in my test state. The crawl found 170 names that wrap.

10. Left alone, and not covered

  • "Effects" (エフェクトの有無) stays as it is. Switching it off made no difference to the sound. It's probably the battle's visual effects, but I haven't checked.
  • "Done" on the settings screen stays under the options column, where the Japanese has it.
  • "Str" / "Mon" for stereo and mono are drawn in the bold font and abbreviated. That's how they were before; I didn't touch them.
  • The card game uses the same renderer in two more overlays (CMENU and CMAIN). The crawler doesn't hook those copies yet.
  • The in-maze settings screen: changed, but I haven't seen it on screen (section 1).
  • "Halycon" in the Compendium's Mythical list is probably Halcyon. It comes from the game's built-in monster names, which are waiting on your decision about the name lists.
